# COBI Evidence AI V4.1 — Generator C Pre-Registration

**Protocol ID:** `cobi-evidence-v4.1-c1.0`  
**Registered:** 2026-11-08, before Generator C generation and label evaluation  
**Status:** synthetic technical research only  
**Decision authority:** none; `EVIDENCE_AI_VALIDATION_BLOCKED`

## Research question and hypotheses

Can semantic-aware financial-evidence representations improve material-defect ranking and critical detection while reducing false-positive review alerts under an independent synthetic distribution shift?

- **H1 — comparability:** semantics-aware validation will reduce alerts on valid differences across non-comparable records versus the frozen V3 baselines.
- **H2 — temporal validity:** explicit effective/requested period and asserted-current semantics will improve recall for stale evidence incorrectly used as current.
- **H3 — source-set transfer:** features based on semantic relationships rather than source-set frequency alone will retain useful performance on a held-out pair of already supported source types.
- Outcomes can be negative or inconclusive. No hypothesis establishes bank performance or safety.

## Phase separation and permitted information

1. Generator B is used only for post-hoc root-cause analysis; all such findings are marked exploratory.
2. Development generator D supplies train, validation, calibration, and a locked development-test partition. Customer groups are disjoint. Hyperparameters are selected on validation only. Probability calibration and operating thresholds use calibration only.
3. Generator C is generated by a separate implementation and seed after this protocol is written. Its observed data may be used to compute predictions after the revised model bundle is frozen. C gold labels remain unopened until the model, threshold, code, and input-manifest hashes are recorded.
4. Canonical truths, event identifiers, corruption flags, and labels are not model-visible features. The semantic representation is limited to values and metadata available from the evidence record/request context.

## Development protocol

- Development generator implementation: `semantic-ledger-dev-v1.1` (Amendment 1 records a pre-training correction to the historical request-period setup in the D4 generator). Seed: `2026110801`; target 6 semantic scenarios × 100 customer groups × 2 cases = 1,200 cases and 600 groups.
- Group split by scenario: 60% train, 15% validation, 15% calibration, 10% locked development test; both cases and every document for a group stay in one partition.
- Models: deterministic CS_V2; original frozen V3 CS_V2/logistic/XGBoost/Deep Sets; semantic rule baseline; logistic regression with semantic features; XGBoost with semantic features; Deep Sets with document and case semantic context; hybrid rules plus learned detection.
- Hyperparameter selection: validation material-defect AP; tie-break by critical recall, then fewer flagged cases. The development-test split is not used for selection or calibration.
- Calibration: Platt scaling fit on the separate calibration partition only. Threshold: among calibrated cutoffs meeting calibration critical recall ≥0.90 and legitimate-document FPR ≤0.20, choose the one with lowest case review workload; ties choose the higher threshold. If no cutoff meets both, select maximum critical recall, then minimum workload, and mark the target unmet.
- Refit policy: selected hyperparameters may be refit on train+validation. Calibration and threshold remain separate and use only calibration data.
- Deep Sets early stopping uses validation AP; the selected epoch is frozen before calibration.

## Generator C mechanism and scenario taxonomy

Generator: `evidence_ai/v4_1_generator_c.py`, implementation ID `semantic-ledger-c-v1.0`, seed `2026110802`. It is implemented independently from Generator B and the development data generator. It uses a new document/ledger construction path, distinct period templates, and a held-out source set; it does not import either generator. It does not reuse B4/B5/B6 records, IDs, parameters, or text templates.

Target sample: 7 scenarios × 120 customer groups × 2 cases = 1,680 cases and 840 groups. Each case has 2–6 records. The held-out individual source pair is `payroll + merchant`; both source types exist in V3, but this pair is omitted from D training. No unseen source type is silently mapped to a known type.

| Scenario | Registered challenge | Gold interpretation |
|---|---|---|
| C1 | Salary components represented as gross, net, and allowance across non-identical pay periods | Valid differences across incompatible bases/periods are not defects |
| C2 | Same income meaning and overlapping period with one material extraction corruption | Corrupted record is material; critical at ≥2× field threshold |
| C3 | Reversed and corrected transaction entries with explicit lineage | Superseded original and correction are not a contradiction by themselves |
| C4 | Old records used for matching historical requests versus asserted current for a later request | Historical-match is valid; stale-as-current is material and critical at age ≥180 days |
| C5 | Numerically different values tied to different subjects/accounts or transaction directions | Non-comparable records do not create a contradiction |
| C6 | Same subject, account, field meaning, direction, and overlapping period with a genuine conflict | Material/critical according to registered field thresholds |
| C7 | Held-out payroll+merchant source set with mixed, valid periods and selected real conflicts | Evaluate source-set transfer; preserve all semantic labels and denominators |

## Metrics and statistical method

Primary: material-defect average precision; critical recall and FNR; B5-like legitimate-discrepancy FPR; C4 stale-as-current recall; case review workload. Secondary: Brier score, log loss, document flag rate, precision at threshold, score calibration, semantic comparability confusion counts, compatibility, and results by scenario/source.

Bootstrap: 500 stratified customer-group draws, seed `2026110803`, with both cases/documents from a sampled group kept together. Scenario-level draws are within scenario. Intervals are percentile 95% intervals conditional on synthetic generators and frozen models; no population guarantee is claimed. Undefined denominators remain null, never replaced by zero.

## Acceptance criteria fixed before C

The semantic hybrid is considered to meet the registered synthetic target only if all are true:

1. Aggregate C critical recall ≥0.90.
2. C4 stale-as-current recall ≥0.90.
3. C1/C3/C5 legitimate-discrepancy FPR ≤0.20.
4. C7 critical recall ≥0.85.
5. Aggregate critical recall is not more than 0.02 below the best frozen baseline's C critical recall.

Report each criterion with its denominator and group-bootstrap interval. Failure or inconclusiveness is a valid result. Passing these synthetic criteria does not imply real-world validity.

## Registered ablation

Train and freeze three semantic-feature logistic ablations using the same D partitions and selection/calibration rules: (A1) remove effective/requested-period and time-validity features; (A2) remove pair comparability and contradiction features; (A3) remove source/provenance and verification features. Compare their C metrics with the full logistic model using paired customer-group bootstrap. These ablations are pre-registered and cannot tune the full model.

## Limitations expected in advance

All data and labels are synthetic and programmatic. Semantics are structured as if extracted; this does not measure extraction accuracy. Scenario coverage is finite, source types are limited, generated evidence may not reflect real document workflows, and calibration/intervals condition on synthetic distributions. Human adjudication, privacy review, and external bank validation are out of scope.
