# Leakage and Validity Threat Model — COBI V4.2

This is a threat model and control plan, not a claim that every threat has been empirically excluded. V4.1 C results remain post-unblinding exploratory. The D1.1 omission is a demonstrated construct/label inconsistency.

| Threat | How it could inflate or distort results | Current evidence/status | Required Phase 2 control |
|---|---|---|---|
| Group/customer leakage | Related cases, documents, duplicate borrowers or counterfactual variants cross splits. | D1.1/C manifests report group splits; no complete new cross-source audit performed in Phase 1. | Split by economic/customer group; verify disjoint IDs/hashes, duplicate clusters, near-duplicates and template families. |
| Generator-rule coupling | Evaluated rules/features share thresholds, templates or semantics with synthetic labels. | V4.1 reports shared numeric tolerance and 180-day stale semantics; D1.1 D4 labels are index-driven and inconsistent with temporal rules. | Independent generator construction, hidden event codes, multiple generators, independent human adjudication and marker controls. |
| Label inconsistency / adjudication bias | Programmatic labels omit valid defects or reflect generator intent rather than observable evidence. | 100 D1.1 candidate stale omissions are reproduced; no human adjudication evidence located. | Preserve raw raters, dual independent annotation, third-rater adjudication, explicit unresolved state, separate world-state and observable truth. |
| Leakage through feature fields | Labels, canonical truth, corruption IDs, group IDs, generator names, future data or evaluation outputs enter features. | V4.1 docs state no such fields are used; this audit did not instrumentally inspect every serialized feature row. | Freeze feature allowlist; schema-level forbidden-key checks; inspect dataflow; permute IDs/markers and verify predictions invariant. |
| Temporal look-ahead | Recorded-after-event amendments or future-period information appears as if available at decision time. | V4.1 schema distinguishes periods but the new benchmark contract is prospective. | Reconstruct as-of snapshots; separate valid/event/recorded times; exclude post-cutoff evidence or label late-arrival challenge explicitly. |
| Provenance/citation leakage | Source IDs or template signatures reveal labels, or explanation cites unsupported spans. | No V4.2 trace evaluation yet. | Hash source artifacts; hide IDs; test marker invariance; independently score document/span support and transformation lineage. |
| Threshold/calibration reuse | Test labels influence threshold, model choice or probability calibration. | C was unblinded; threshold is frozen, but C is exploratory and cannot be reused for confirmation. | Separate training/validation/calibration/sealed test groups; log label access; hash predictions/config before unblinding. |
| Repeated test/benchmark adaptation | Iterative changes after test inspection turn an evaluation set into development data. | V4.1 C already opened; no new V4.2 test exists. | Mark post-unblind datasets as development/exploratory; create a new independently sealed test for any confirmatory claim. |
| Candidate-family selection / multiplicity | Many models/ablations are tried and only favorable results reported. | V4.1 Semantic XGBoost is `NOT_EVALUATED`; historical family is incomplete for that arm. | Freeze full candidate/ablation family; predeclare primary comparisons and use Holm correction; disclose all arms. |
| Prevalence / synthetic scenario mix | Balanced scenario construction makes PPV, workload or costs unlike a target population. | C is synthetic and scenario prevalence is design-chosen. | Report support and scenario frequencies; evaluate multiple prevalence strata and transparent reweighting; do not infer bank PPV/savings. |
| OCR/extraction confounding | Low-quality extraction is mistaken for semantic evidence error or groups leak through template. | V4.1 text/structured data are simulated; no real OCR validation in V4.2. | Evaluate oracle-extraction and end-to-end modes separately; stratify quality; retain extraction confidence and source spans. |
| Attribution/fraud overclaim | Pair conflict is converted into “which document is wrong” or fraud. | V4.2 ontology deliberately separates pair relation and attribution. | Require independently verified attribution evidence; no fraud label; audit UI/API output language and keep research read-only. |
| Distribution-shift overclaim | Exchangeability or calibrated risk guarantee is assumed under source, time or policy change. | No independent shift evaluation; conformal guarantees are assumption-dependent. | Predefine shift axes and split; test worst-group bounds; require explicit domain-owner epsilon and valid confidence assumptions. |
| Product/authority leakage | Research score influences affordability, routing, officer authority or credit approval. | Existing V4.1 UI/API is documented read-only; Phase 1 changes are confined to `research/v4_2/`. | Keep research outputs isolated; code-level test that no research API feeds product decisions; require separate approval and evidence for any future integration. |
| Reproducibility and artifact substitution | Reports do not match code/data, environment or frozen artifacts. | C prediction digest verifies; protected V4 manifest remains 95/96 due a pre-existing frontend artifact mismatch; final V4.1 package log says 100/100 for a different manifest. | Record manifest/file hashes and actual commands/exit codes; preserve mismatches; rerun only allowed scoped tests; review exact artifacts. |

## Inference boundaries

- Generator C measurements are already unblinded, finite-synthetic, and post-unblinding exploratory.
- D1.1 label inconsistency weakens temporal-feature learning/effect claims across every development split.
- No human bank evidence, independently adjudicated bank defect labels, approved economic risk tolerance, or deployment monitoring are present in this Phase 1 package.
- No claimed metric implies credit decision quality, fraud attribution, regulatory readiness, loss reduction or operational savings.
| Timestamp disagreement / duplicate claim records | Conflicting source issue times or repeated representations are silently ordered, collapsed or treated as independent ground truth. | New schema records source-issued time separately; edge fixtures include conflicting timestamps and linked multi-record claims. | Keep record IDs and provenance separate; preserve unknown ordering; test repeated claims across splits; require approved authority/supersession rules. |
